# gate

layer devkit, status built

Version 0.7: the number of this file's change list, below, and of nothing else

- **Holds:** the test framework's module, by its design, below `tools/gate.py`, its one consumer: `key.py`, each file's digest by git, a test's modules, its key and the checkout's code id; `junit.py`, each selected test's outcome read from CTest's JUnit (D-6); `states.py`, a test's record, its state and colour, why it is selected, and each transition of the design's table of the states, with the gone and a failed build's red; `store.py`, the store of one configuration under `.local/states/<preset>/`: its lock, `state.json` with its format, a run's journal, the tree's and the run's ids, the retention of the runs' files, and another configuration's `state.json` read for its reds; `selection.py`, the selection by key, the ask and the plan's expected time; `gates.py`, a gates file read and checked, its steps, each configuration's owners and whether a step's reach leaves it out; `run.py`, a step's run in the order of a run, from its lock to its answer, the build tools reached through a runner; `envelope.py`, the codes, the next action and the answer's one line within its bound, a gate's from its steps'; its tests in `tests/`, label `gate`
- **Never holds:** a command line, a gate's steps or its data (`tools/gate.py`, `tools/gates.json`); a start of a build tool, which `python`'s `build_tree` makes; a call to the system or to git, which `python`'s `system` and `git` make; a result carried: a record names an earlier run's outcome as that run's
- **Contract:** none
- **Interface:** no header: the package `foundation.devkit.test.gate`, imported normally, as `python`'s README says of a script under `-I`. Its members, by file, are in the method's Members lines below; a name used only inside its file takes a leading underscore
- **Files:** `__init__.py`, `key.py`, `junit.py`, `states.py`, `store.py`, `selection.py`, `gates.py`, `run.py`, `envelope.py`, `tests/` and this directory's `module.json`
- **Consumers rely on:** a test's key and the code id by `key` alone, its files' digests git's blob ids; an outcome by `junit.read` alone, every selected test answered, `not_started` for one that did not start; a record's change by `states.after` alone, which makes no transition for a `not_started`; the store by `store` alone: one run a configuration under its lock, `state.json` replaced whole or not at all, an unreadable one `Internal`, never no store; a step's answer by `run.step` alone, which never raises for the store, the tools or the table but answers their code; the line by `envelope.answer` alone, never past its bound, every red in it named or counted
- **Parameters:** none
- **Refuses:** a test of no module of the table, `key.NoModule`; a store another run holds, `store.Locked`, naming its holder; a `state.json` or a tree's id it cannot read, after 5 tries over 2 s where the file is held, `store.Unreadable`; a write that fails, after the same tries, `store.WriteFailed`; the last two are `store.Internal`

The method for `key`:

- **Members:** `Files`, `(modules, unowned)`: `modules`, each module of the table to `{path: blob id}` of its files, its first owner's (`table.owners`), an empty dictionary for a module git lists no file of; `unowned`, `{path: blob id}` of the files in no module; `files(root, table, env=None)`, the `Files` of git's listing (`git.blob_ids`); `is_document(path)`, a `.md`; `is_python_test(path)`, a `test_*.py`; `CHECKS`, `("rules", "exemptions")`, the names of the checks of a module, `<check>.<M>`; `modules_of(name, labels, modules)`, `(the test's modules in name order, the modules that enter whole)`: its labels that name a module, and, for a check test, M, which enters with all its files; `own_file(name, paths)`, a Python test's own `test_*.py` among `paths`, by its name's dotted path, the longest that matches, or `None`; `test_key(preset, name, labels, files)`, the test's key, 64 hex digits; `bare_key(preset, name)`, a test of no module's key in a step that runs all, its configuration and name alone; `code_id(files)`, the checkout's, 64 hex digits; `NoModule`, a test whose labels name no module
- **The key:** the SHA-256 of the JSON of `[preset, [[module, [[path, id], ...]], ...], own]`, the modules in name order and each one's paths in order; a module's documents and `test_*.py` out but for a module that enters whole; `own`, `[path, id]` of the test's own file where it is a Python test and its module does not enter whole, else `null`. The code id: the SHA-256 of the JSON of `[[path, id], ...]` of every file of `Files` but the documents, in path order. Neither holds the store's format, the tree's id or the other, none of which of itself ends a red
- **Compatibility:** no call to the system: `hashlib` and `json` over git's answer, which `python`'s `git` reads the same on every system
- **Extensibility:** another check of a module is one more name in `CHECKS`; another language's narrowing, as Python's own file, is one more branch beside `own_file`
- **Performance:** one `git.blob_ids` a run, three or four runs of git, and `table.owners` over the listing, about 0.1 s at this checkout's size by `table`'s README, not measured here; a key is one hash over its modules' paths, for each test listed
- **A fake:** none: its input is git's real answer, and its tests plant `Files` themselves. Its proof: `tests/test_key.py`, the key's parts and their order, a document and a Python test file out, the own file in, a check test's module whole; `files` by `tools/gate.py`'s use
- **Errors:** `NoModule`, naming the test and its labels, which the gate answers as a listing error, `BUILD_FAILED`. `git.GitFailed` from `files` is unwrapped, the caller's to word

The method for `junit`:

- **Members:** `OUTCOMES`, `("passed", "skipped", "timeout", "crashed", "failed")`; `GREEN`, the first two; `NOT_STARTED`, `"not_started"`, no outcome and no colour; `SKIPS`, the two messages of a skip; `Ran`, `(outcome, seconds, why)`: the outcome or `NOT_STARTED`, the test's seconds or `None`, and why, the JUnit's message trimmed, the watcher's last line, a skip's reason from the case's `SKIP <name>: <reason>` line (both runners print it) else CTest's message, or the reason it did not start; `outcome(status, message, last)`, `(outcome, why)` of one `testcase`'s `status`, its message and its output's last line; `read(path, selected)`, `{name: Ran}` for each name of `selected`
- **The reading:** `run` is `passed`; `notrun` with a skip's message, `skipped`, any other `notrun`, `NOT_STARTED`; `fail` with the message `Timeout`, or a last line `status: 124 ...`, `timeout`; `fail` with the message `SEGFAULT` or `Exit code 0x...`, or a last line naming a system status (`status: 0x...`), a signal (`status: signal ...`) or the C runtime's abort (`status: 3 ...`), `crashed`; any other `fail`, `failed`; any other status (`disabled`), no `testcase`, no JUnit or a JUnit that does not parse, `NOT_STARTED`. A message is trimmed of white space. The last line is the output's last that is not blank, which `--test-output-truncation head` keeps
- **Compatibility:** `xml.etree.ElementTree` over CTest's file, the same on every system: one producer, CTest 4.4.3 here. Its form read once against a real `ctest --output-junit` of `build/ci-windows`, a pass, a planted skip and a planted failure: a `testcase` a test, `status` `run`, `notrun` or `fail`, a `skipped` or `failure` element with its message, a `properties` element, the output in `system-out` with the watcher's line last, as the reading takes it
- **Extensibility:** another outcome is a row of the reading and of `OUTCOMES`, with its colour
- **Performance:** one parse of the run's JUnit, held whole in memory: the output of each test CTest kept in it
- **A fake:** none: its tests plant JUnit files in CTest's form. Its proof: `tests/test_junit.py`, each row of the reading and each way not to start
- **Errors:** none raised: what cannot be read is `NOT_STARTED`, with its reason

The method for `states`:

- **Members:** a record is a dictionary, `key`, `tree`, `code`, `outcome`, `flaky`, `since`, `flips`, `seconds`, and `run`'s `modules` and `labels` of its last listing, read for a red's owner; `colour(record)`, `"green"` or `"red"`, a flake red; `state(record)`, its outcome or `"flaky"`; `is_red(record)`; `reason(record, key, tree)`, why the key selects it: `"new"` with no record, `"changed"` at another key, `"rebuilt"` at this key and another tree, `None` at both, left out unless asked; `after(record, key, tree, code, run, ran)`, the record after `ran`, a `junit.Ran`, at `run`, a new dictionary, or the record itself for a `NOT_STARTED` and for a skip of a red record; `gone(tests, listed)`, the names of the records the listing names no more, sorted; `build_failed(state, run, lines)` and `build_passed(state)`, a configuration's failed build's red in its `state.json`, kept, its `since` the first failed run, until its tree builds
- **The transitions,** the design's table: with no record or at another key, the outcome, `since` this run, the flips kept, 0 where new. At this key, from green: a green keeps `since`; a red begins `since` this run, flips + 1 at the same code id. From red: a green at the same code id is `flaky`, `since` kept, flips + 1; at another, green, `since` this run, a fix outside the key; a red keeps `since`. From `flaky`: a green at the same code id stays `flaky`; at another, green, `since` this run, the flake ended; a red is red, `since` kept, flips + 1 at the same code id. At this key and another tree the record's own row holds. A skip ends no red, the reviewer's ruling on the gate's finding G-2: a red or `flaky` record skipped, at any key, tree or code id, a red at another key among them, is kept as it was, its outcome, `since`, flips and code id, no flake; it ends only by a pass at another code id than the one it was red at, and until then a record at another key or tree is selected again each run, `changed` or `rebuilt`. A new or green record skipped is as passed, green, never counted passed. Every transition takes the key, the tree, the code id and the seconds of the run; a `NOT_STARTED` and a red's skip take none
- **Compatibility:** no call: dictionaries
- **Extensibility:** another state is one more branch of `after`, with its row in the design's table
- **Performance:** a dictionary's copy a test that ran
- **A fake:** none needed. Its proof: `tests/test_states.py`, the table row by row, and a skip of each
- **Errors:** none of its own: a record without its fields raises the language's `KeyError`

The method for `store`:

- **Members:** `FORMAT`, 1; `LOCK_OFFSET`, `1 << 30`; `TRIES`, 5, and `TRY_SECONDS`, 0.5, between them; `KEEP`, 20 runs; `place(root, preset)`, `<root>/.local/states/<preset>`; `lock(place, argv)`, a `Lock`, the store's, its holder (pid, start, argv) written at byte 0, `Lock.release()`, also by `with`; `Locked`, its `holder`, a dictionary, empty where unread; `empty(preset)`, a new `state.json`'s dictionary; `read(place)`, the `state.json` or `None` where none is; `write(place, state)`, by `state.json.tmp`, flushed and synced, then `os.replace`; `others(root, preset)`, `{preset: state}` of every other configuration's store, read without its lock; `tree_id(tree)`, the tree's `states.id`, 16 hex digits from `os.urandom`, written where absent; `run_id(now=None)`, `<UTC yyyymmddThhmmssZ>-<4 hex>`; `spelled(run)`, `run:<id>`; `Journal(place, run)`, `runs/<run>.jsonl`, `write(kind, **fields)` a line flushed, `close()`, also by `with`; `run_file(place, run, suffix)`, the path of a run's `.log` or `.xml`; `unended(place)`, the runs whose journal has no `end` line; `retain(place, cited)`, the newest `KEEP` runs' files and each run of `cited` kept, the rest removed, the faults' lines answered; `Internal`, with `Unreadable` and `WriteFailed`
- **Compatibility:** the lock is `system.lock_byte` on one byte at `LOCK_OFFSET` of the `lock` file, the holder at byte 0 outside it, so that a second run reads it: Windows' lock is mandatory. `os.replace` is `MoveFileExW`, which fails with `PermissionError` while another process holds the file open, a reader of another configuration among them (St-6): each read and write takes `TRIES` over 2 s. Paths by `pathlib`, the same on every system
- **Extensibility:** a second format is a second value of `FORMAT` and a move of every record by the commit that makes it; another file of a run is another suffix of `run_file`
- **Performance:** `state.json` is read whole and written whole once a run, its size about 200 bytes a test listed, not measured; `retain` and `unended` list `runs/` and read each journal's last line
- **A fake:** none: its tests plant the store in a scratch directory. Its proof: `tests/test_store.py`, the replacement whole, the lock held and its holder read by a second process, the tries, an unreadable store `Unreadable`, the ids' forms and the retention
- **Errors:** `Locked` names the holder, for the gate's `STORE_LOCKED`. `Unreadable`, `<file>: <reason>`: a file still held after the tries, one that does not parse, is not an object or lacks a field of `empty`'s; `WriteFailed`, `<file>: <reason>`: the gate's `INTERNAL` for both. A store removed by hand is `None`, no store, the one loss it cannot refuse. `retain` raises nothing: each file it cannot remove is a fault line

The method for `selection`:

- **Members:** `ASKS`, `("test", "module", "red")`; `Ask`, `(kind, name)`, `name` `None` for `red`; `ask(text)`, the `Ask` that `test:<name>`, `module:<name>` or `red` spells, `ValueError` for any other text, the command line's usage error; `spelled(ask)`, as written; `asked(ask, name, labels, record)`, whether the ask names that test, by the ask's rule below, `record` its record or `None`, the one rule `choose` and `gates.out_of_reach` read; `Selection`, `(selected, left_out, unmatched)`: `selected`, `{name: reason}` in the listing's order, `new`, `changed`, `rebuilt` or `asked`; `left_out`, `{name: {"colour", "since"}}`; `unmatched`, the asks' texts that name no test, `red` never among them; `choose(listed, records, keys, tree, asks=(), every=False)`, the selection of `{name: labels}` by the records, the keys and the tree's id, `every` a step's `select: all`; `Plan`, `(tests, seconds, unknown)`; `plan(names, records, jobs)`, the larger of the last durations' sum over the jobs and the longest one, a test with no duration counted in `unknown`
- **The ask:** `test:<name>` the test of that name; `module:<name>` each test a label of which names it; `red` each test whose record is red, a flake among them, of the step's own configuration. An ask adds and narrows nothing; a test the key selects keeps the key's reason. `red` with no red kept adds nothing and is no `NO_TESTS` (the lead's answer, turn 93)
- **Compatibility:** no call: dictionaries
- **Extensibility:** another ask is one more kind in `ASKS` and one more branch of `asked`
- **Performance:** one pass over the listing, each ask tried on each test
- **A fake:** none needed. Its proof: `tests/test_selection.py`, each reason, each ask, `every` and the plan's time
- **Errors:** `ValueError` from `ask` alone

The method for `gates`:

- **Members:** `FORMAT`, 1, a gates file's; `BadGates`, a gates file unreadable or not in its form, one line naming where; `load(path)`, the gates file's data, checked: its format and toolset, each owner a gate of it, each gate's steps, each step a preset and only `preset`, `source`, `select`, `labels`, `pattern`, `repeat` and `reach`, its first step with no reach; `steps_of(gate, root)`, `[(run.Step, its reach or None)]`, each step's targets its build preset's in root's presets files (`run.targets`); `owners_of(data)`, `{preset: [(gate, labels, pattern)]}`, of the gate the owners name for the preset, then of `envelope.OWNER`, each one's step of that preset (`envelope.owner`); `matcher(reach, trees)`, whether a path from the root is in a reach, `trees` the table's trees; `out_of_reach(root, step, reach, files, trees, asks=())`, why a step is left out by its reach, or `None` where it runs, a kept build red of its configuration among them
- **The reach:** a step runs where its configuration has no store or an unreadable one (its own answer names it), where its `state.json` holds a kept build red (`build` not null), whatever its reach and asks, so that its build runs and the change that fixes the build, wherever it lies, ends the red, where a file of its reach changed since its configuration's last run (git's blob ids, `key.Files`, against its `state.json`'s), or where an ask names a test it lists by its store's records, each test's labels its record's (`selection.asked`, `envelope.lists`): an ask adds to the selection whatever the step's reach. Else it is left out, its reason the run it stands on, and, with asks, that no ask names a test it lists. A reach is `paths`, each a path or a directory ending in `/`, or `trees` with `suffixes`, names of `trees.json`'s lists, a suffix itself where it starts with `.`
- **Compatibility:** one `json` read of the file and one of a `state.json`: no call to the system
- **Extensibility:** another step field is one more name in `STEP_FIELDS` and its check in `load`; another reach, one more field in `REACH_FIELDS` and its part of `matcher`
- **Performance:** a step's reach reads its configuration's `state.json` once, before its build, each ask tried on each record
- **A fake:** none needed. Its proof: `tests/test_gates.py`, on planted gates files and a planted store: each refusal of `load`, the steps with their targets, the owners and a red's ask, `commit`'s for a release red its step lists, the matcher, and the reach by files, by asks and by a kept build red
- **Errors:** `BadGates` from `load` alone; a store `out_of_reach` cannot read runs the step

The method for `run`:

- **Members:** `Step`, `(preset, source, every, labels, pattern, repeat, targets)`, a gate's step: `source` `"."` or `"foundation"`, whose presets file names the preset; `every`, `select: all`; `labels` and `pattern`, regular expressions one of a test's labels or its name must match, else `None`; a step of a gate of several runs its selection and leaves the ask to the gate's answer
- **The order of a run:** the lock; the store, the runs that never ended and the other stores; the tools (`tools()`, a callable, raising `Missing`); the table; the journal, each run that never ended named once by an end line appended to its journal, `ended: false`, `ended_by` this run, and a fault line; the tree's id and git's listing, read before the build for the journal's header, which holds the code id (git's listing is the sources, which the build does not change), git failing there `INTERNAL`, the journal's end line written (G-7); the build, its output in `runs/<run>.build.log`; the listing and the keys, a listing error or a test of no module in a keyed step (`select: changed`) a failed build's red, a test of no module in a step that runs all (the fuzz targets, `cxx;fuzz`) run and recorded under `key.bare_key`, no module; the selection, each `selected` and `left_out` line in the journal; ctest by the runner with the step's repeat; the JUnit, an `outcome` line a test; the transitions; the gone tests and configurations, named at the listing, their reds ended, their records and stores dropped, only where the run writes `state.json`; `state.json`, the failed build's red ended there; retention, citing each red's `since` and log; the end line; the answer. A plan writes its journal and the build's red alone, no test record and no `modules`, no red ended and no store dropped: a failed build's red, a gone test's and a gone configuration's kept and named, none as ended (G-6)
- **The codes,** `envelope.CODES` in order: `INTERNAL` for a store that cannot be read or written, git failing mid-step, or ctest's exit against its JUnit (0 with a red or a test not started, or else non-zero with neither); `NOT_STARTED`, a selected test that did not start, each of them where ctest itself could not start or was killed, with no JUnit; `INTERRUPTED`; `BUILD_FAILED`; `NO_TESTS` for a tree or a step that lists no test, or an ask no test of a step alone carries (of a gate of several steps, `envelope.answer`'s, where no step lists it); `TESTS_FAILED`; `TESTS_FLAKY`, a test passed this run at the code id it was red at, a skip never; `RED_KEPT`, a red of this configuration or of another; `PLANNED`, a plan that selects a test, `pending`, not ok (main's ruling, turn 93: a plan ran none of its selection, so an ok could be read as the gate's green), its next action the gate's command without `--plan`; `PASSED`; `NOTHING_TO_RUN`
- **Compatibility:** `Runner` calls `system` and `build_tree` alone; the rest is files under `pathlib`, the same on every system
- **Extensibility:** another point of a run is one more stage in `step`'s order; another tool is another runner method; a fake runner is any object with the three methods
- **Performance:** a key a test listed, each over its modules' files; a journal line a test; one JUnit parse; `state.json` written once
- **A fake:** its tests' `Fake` runner, a build of a status given, a planted listing and a ctest that writes a planted JUnit, over a scratch root and planted `Files` and table. - **Errors:** none raised for the store, the tools, the table, git, the build, the listing or ctest: each is its code. A fault of the code itself raises
