- **Consumers rely on:** a package's tests loaded by its one line, `load_tests = skip.loader(__file__)`, and a run of skipped tests alone ending with the skip code, 125; a binary's cases listed by name (`--list`) and each run alone by its name (`--run`), its status the one CTest reads (pass 0, fail 1, skip 125); each case's allocators counted after it; every test behind the watcher, its status named in one last line on standard error and its exit the case's, and a case past its limit a hang, its stacks and its dump written and its tree ended, status 124; a watched run from Python by `run_watched` alone, no test starting the watcher itself
- **Parameters:** none
- **Refuses:** two cases of one name, or a name that begins or ends with its dot, and a case or an argument it does not know: usage, status 2; a case that leaves an allocation of its own held: the case fails. The watcher: no `--limit` or `--name`, or no command after `--`, its usage, status 2; a case that cannot start, `watch.py: <test>: the case cannot start: <reason>`, clipped, status 2
- **Words:**
  - `case`: one test body registered by `QIVEN_CASE`, run by name

The watcher, `watch.py`:

- **What it does:** `python -I -X faulthandler foundation/devkit/test/runner/watch.py --limit <s> --name <test> -- <command>...` runs the case and names how it ended. It sets `QIVEN_WATCHER`, its own process id, and, with `QIVEN_BUILD` naming the build, `QIVEN_DUMP_DIR`, the build's `dumps/`, and `QIVEN_LOG`, `logs/<test>.jsonl`, each directory made. It sets the quiet load-error mode first (`system.quiet_load_errors`), which the case inherits; the case inherits its standard output, its standard input closed, and its standard error is relayed line by line. Then one line on standard error names the status by `status`'s table, and on a library missing at load the imports found nowhere the loader looks, by `python`'s `imports`, imported normally. It exits with the case's status, a POSIX signal as 128 and its number. After every case, a hang's or not, it bounds the build's `dumps/` by `dumps.py`
- **The hang:** past `--limit`, `debugger.hang_stacks` (the pinned cdb, or a CI image's, unpinned): `hang: past its limit of <s> s, <n> threads` and every thread's stack, at most 16 threads and 200 lines, and `<binary>-<pid>-hang.dmp` in `dumps/` (`dumps.py`'s `hang_dump`); with no debugger, `hang: no debugger, no stacks` and the reason. Then it ends the case's tree, names what it wrote and the case, `status: 124 hang: ...; <written>; <test> past <s> s`, and exits 124. Its worst case, against the 30 s CTest leaves it after a case's limit (`ctest_tests.cmake`'s `AFTER_LIMIT`), is in `debugger`'s charter (`foundation/devkit/python/README.md`): the watcher's `HANG_SECONDS`, 12 s, reckoned beside `READER_WAIT` in `watch.py` and given to `hang_stacks`, finding the debugger and its stacks together, `process`'s ending of cdb, the case's ending and `READER_WAIT`, 5 s, for the case's stream
- **Its consumers:** `ctest_tests.cmake`, every test's command; `binaries.py`'s `WATCHER`, which `run_watched` runs; `tools/debug.py`, which drops the watcher from a test's command by its name, `watch.py`
- **Compatibility:** Windows built; POSIX and macOS on paper through `process`, `system`, `debugger` and the 128 and a signal's number of its exit, its imports' reader PE's alone, no Linux build. Linux's symbolizing and loader path are retired (`tools/README.md`'s Retired section)
- **Performance:** it loads `answer`, `debugger`, `imports`, `process`, `status`, `system` and the dumps' bound at its start, in front of every test. Measured once by a probe in scratch (interpreter 3.15.0 under `-I -B`, the median of 15 runs, while `debugger` still imported `build_tree`, before `1612fde`): a case behind the watcher took 115.6 ms where the interpreter alone took 25.6 ms, about 90 ms a test; our imports 27.6 ms of it, `debugger` 20.9 ms with `process`, `system`, `status` and then `build_tree`, `imports` 4.6 ms, `answer` 1.2 ms, the dumps' bound 0.9 ms. Not changed for it; `system`'s and `process`'s charters give theirs
- **A fake:** none: it stands in front of the real case. Its tests, `tests/test_hang.py`, run it with a stand-in cdb (`cdb.cmd`) on `PATH` for a CI image's path and a sleeping interpreter as the case (`Hang`, label `fake`), and K8, a real hang under the pinned cdb (`HangStacks`, label `debugger`); every test CTest runs stands behind it, and `test_wiring.py`'s `test_properties` holds each test's command to `WATCHER`
- **Errors:** its own lines name it: `watch.py: <test>: the case cannot start: <reason>`; `hang: no debugger, no stacks` and `hang: <reason>`; the status line's `; its imports cannot be read` or `; not found: <library>, ...`. Each line of its own that carries a name, a path or an error's words (the failed start's, the hang's reason, both status lines) is held within `answer`'s `LINE_POINTS` by `answer.clip`, the cut named; the hang's first line is within it by its form, and its stacks are bounded by `debugger`

The dumps' bound, `dumps.py`:

- **What it does:** `bound(directory, pid=None, kept=DUMPS_KEPT)`, `DUMPS_KEPT` 8: a dump is a file `*.dmp` of the directory, nothing else read or removed; ordered by its last write and then its name, the newest `kept` stay, and every dump of process `pid` (`<binary>-<pid>.dmp`, `<binary>-<pid>-hang.dmp`), so that the dump a case's report or a hang's lines name is never removed. `hang_dump(pid, binary, directory)` forms the hang dump's path, `<binary>-<pid>-hang.dmp` in the directory, or `None` where none is given, the one place the name is formed: the watcher passes it to `debugger.hang_stacks` and names it, and `bound` reads the same form. It answers a line for each dump removed, `dumps: removed <name>, past the newest <kept>`, or that cannot be removed, `dumps: cannot remove <name>: <reason>`; one another process removed first gives no line, and no directory none
- **Its consumers:** the watcher, after every case; `run_watched` drops its two lines from the watcher's standard error, since another case's dump, written beside, may give them in any run
- **Compatibility, performance and a fake:** `pathlib` alone, the same on every system; not measured; none, a directory being its input. No test of its own: every watched run reaches it

`run_watched`, in `binaries.py`:

- **What it does:** `run_watched(command, name, env=None, cwd=None, limit=TIME_BOUND)` runs the command behind the watcher, by this interpreter under `-I -X faulthandler`, as CTest runs it, `--limit` the limit given, `TIME_BOUND`, 10 s, unless given; it polls every `POLL`, 0.1 s, for the visible windows of the watcher and its children, ends the watcher's tree where it still runs past the limit and twice `AFTER`, 30 s, the time CTest leaves the watcher past a case's limit, and answers `(status, out, err, seconds, seen)`, the output as bytes, `err` without the dumps' bound's lines. It is the one watched run from Python
- **Its consumers:** diag's `tests/test_faults.py`; `build`'s `tests/test_hardened.py`; `tools/tests/test_debug.py`; this module's `tests/test_hang.py`, which gives its own limits

`loader`, in `skip.py`:

- **What it does:** `loader(init)`, given a package's `__file__`, returns its `load_tests`, unittest's protocol, called as `load_tests(loader, tests, pattern)` when discover or a name reaches the package: it adds the tests discover finds under the package's directory by `pattern` (`test*.py` where discover passes none) to `tests`, sets `sys.exit` to `exit_with_skip`, which unittest's main looks up when it ends the run, and returns the whole in a `Run`, which keeps the result, so that a run of skipped tests alone ends with `SKIP_CODE`, 125. It owns the one body each package's `__init__.py` held a copy of (`8873d5c`)
- **Its consumers:** every test package's `__init__.py`, one line, `load_tests = skip.loader(__file__)`: `foundation/core/memory/tests`, `foundation/core/time/tests`, `foundation/devkit/build/tests`, `foundation/devkit/python/tests`, `foundation/devkit/structure/tests`, this module's `tests`, `foundation/services/compute/tests`, `foundation/services/log/tests`, `foundation/system/diag/tests`, `products/qiven3/tests`, `tests` and `tools/tests`
- **Compatibility:** the standard library alone (`os.path`, `unittest`, `sys`), no system call: the same on every system; Windows observed, POSIX and macOS on paper, no Linux build
- **Extensibility:** a package that needs more wraps the function it returns; none does
- **Performance:** one closure a package and the same walk of discover as each copy made; not measured
- **A fake:** none: it is the run's own loading, used by every Python test run and by `test_wiring.py`'s samples, whose exits it gives
- **Errors:** none of its own. A test module that fails to import surfaces as unittest's failed test; a wrong `init` gives the wrong directory, which it does not check
